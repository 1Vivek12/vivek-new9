# ADR-0005: Media & Video Production Subsystem Architecture

## Status
Accepted

## Context
In modern newsroom workflows, raw video, audio recordings, press conference streams, and eyewitness footage arrive continuously. To enable rapid story turnaround, editors require automated technical validation, speech transcription, visual scene boundary detection, OCR text extraction, subtitle generation, and derivative formatting (e.g. 9:16 vertical video for mobile discovery).

However, introducing heavy media processing into a multi-tenant platform creates critical security, operational, and architectural risks:
1. **Command Injection & Process Safety**: Invoking tools like FFmpeg or Whisper via shell strings poses severe command injection vulnerabilities.
2. **Synthetic vs Real Boundary**: If external binaries (FFmpeg, Whisper, Tesseract) are not present in a given hosting environment, the system must not fake successful processing as if real analysis occurred.
3. **Cross-Tenant Leaks**: Media files are large binary blobs that cannot leak across tenant boundaries.
4. **Copyright & Rights Violations**: Processing or publishing copyrighted or restricted third-party wire material exposes the newsroom to legal liability.
5. **Phase Boundary**: External publishing to YouTube, Facebook, Instagram, or public websites belongs strictly to Phase 6 and must not be triggered in Phase 5.

## Decisions

### 1. Subprocess Hardening
- Subprocess execution strictly uses argument arrays (`list[str]`), never `shell=True`.
- Process environment variables are sanitized: sensitive secrets (`DATABASE_URL`, `REDIS_URL`, `SECRET_KEY`, `JWT_SECRET_KEY`) are stripped before subprocess invocation.
- Subprocesses execute with mandatory timeout guards (`kill()` on timeout).
- Subprocess stdout/stderr are captured with length bounds (max 500 characters in public error messages) to prevent secret leakage or unbounded memory consumption.

### 2. Strict Real vs Mock Separation
- Production processors (`FFmpegMediaProcessor`, `LocalWhisperProvider`, `FFmpegSceneDetector`, `LocalOCRProvider`) probe binary availability. When tools are absent, they raise `ToolUnavailableError` and set job status to `TOOL_UNAVAILABLE` or `FAILED`. Under no circumstances do they fake successful data.
- Mock providers are strictly test-only fixtures with `IS_MOCK = True` and are never exposed to API callers.

### 3. Server-Side Rights Policy
- Every media asset has declared `rights_type` (`OWNED`, `LICENSED`, `USER_PROVIDED`, `RESTRICTED`, `UNKNOWN`).
- `RESTRICTED` rights strictly blocks derivative generation with HTTP 403.
- `UNKNOWN` rights requires human review.
- `USER_PROVIDED` requires `reuse_permitted=True`.

### 4. Signed Short-Lived Tokens for Streaming
- Direct access to media storage files is prevented.
- Playback and streaming require HMAC-SHA256 signed short-lived tokens (15-minute expiry) binding `tenant_id`, `media_id`, and `user_id`.

### 5. Mandatory Human Review Gates
- Clip candidates and thumbnail cards generated by automated analysis enter `SUGGESTED` or `CANDIDATE` status.
- Transition to `ACCEPTED` requires human review by an `EDITOR` or `ADMIN`.
- Rejection requires an explicit editorial reason.

## Consequences
- **Positive**: Complete multi-tenant isolation, process security, legal copyright compliance, and clear architectural boundary between test fixtures and production execution.
- **Negative**: Environments without FFmpeg/Whisper will report `TOOL_UNAVAILABLE` jobs for media analysis until system binaries are installed in the host container.
